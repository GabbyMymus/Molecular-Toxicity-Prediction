# Viva drill, Phase 2 (deep learning): likely questions, short answers, evidence

Same idea as `docs/viva_drill.md`: each answer points to the file or commit it comes from so you can open it and quote it.
Numbers were recomputed from the committed result files in `results/` (mean over the 12 endpoints, then mean over seeds 0, 1, 2; the "±" is the sample standard deviation over seeds, as in `report_phase2/sections/hybrid.tex`). All results are test-split numbers from the final runs, scaffold split unless stated. Items marked **UNVERIFIED** could not be checked from the repo. The quiz itself has not been run with the team.

Abbreviations: D0 FP-MLP, D1 GCN, D2 MPNN, H1 MPNN with descriptors, H2 rank-average ensemble.

## 1. Protocol

| # | Question | Short answer | Evidence |
|---|---|---|---|
| 1 | Why a scaffold split? | A random split lets near-identical molecules sit in train and test; grouping by Bemis-Murcko scaffold puts whole ring systems on one side, so the test measures generalization to new chemotypes. All acyclic molecules share one empty scaffold and land in training. Phase 2 reuses the Phase 1 split files unchanged. | `src/splits.py::scaffold_split`; `src/dl/split_io.py`; `README.md` (Dataset and evaluation); `docs/viva_drill.md` (mean max Tanimoto test-to-train 0.428 scaffold vs 0.584 random, quoted from that file, not re-run here). |
| 2 | Why a masked loss? | A missing label means "not tested", not "inactive". NaN entries contribute exactly zero to the loss and the sum is divided by the number of labeled entries. Treating NaN as 0 is the deliberately wrong ablation `mask_missing=false`. | `src/dl/train.py::masked_bce_with_logits`; `tests/test_dl_smoke.py::test_masked_loss_matches_manual_and_ignores_nan`, `::test_unmasked_variant_treats_nan_as_negative`; `CONTRACT.md`. |
| 3 | Why `pos_weight = n_neg / n_pos`, capped at 50? | Positives are rare, so each endpoint's positive class is up-weighted by its own training imbalance. Weights are computed per endpoint on labeled training rows only. On the committed splits the cap never binds: the largest uncapped weight is 38.35 (scaffold) and 34.57 (random). **UNVERIFIED:** why 50 was chosen; the repo records the value, not the reason. | `src/dl/train.py::compute_pos_weight`, `DEFAULTS`; `tests/test_dl_smoke.py::test_pos_weight_is_per_endpoint_n_neg_over_n_pos`; weights recomputed this session with `compute_pos_weight` on `data/splits/*_seed0.json`. |
| 4 | Why early-stop on validation PR AUC rather than ROC AUC or loss? | The mean validation PR AUC over the 12 endpoints is the stopping and selection signal (patience 10, max 60 epochs, best weights restored). PR AUC is the metric that stays informative at 2.91% to 15.94% positive rates. **UNVERIFIED:** the team's stated reason for choosing PR AUC for stopping; the README gives the reason PR AUC is reported, not the reason for stopping on it. | `src/dl/train.py::fit`; `README.md` (positive rates); `docs/viva_drill.md` (PR AUC row). |
| 5 | What is the freeze commit 0aebd87 and why does it exist? | It is the commit (2026-11-15 03:09:09 +0530, "FREEZE: DL configs frozen before any test evaluation") that adds only `results/best_configs_dl.json`. It fixes the hyperparameters before any test-set result file is committed, so test scores cannot influence them. The first DL test-result commits are later (`8547142` 04:23:06, `54910cd` 15:50:09, `60dccb4` 16:08:12). Phase 1 did the same with `041892c`. **UNVERIFIED:** that no test evaluation was run locally before the freeze; git only shows what was committed. | `git show --stat 0aebd87`; `git log` timestamps for the commits above; `report_phase2/sections/methods.tex` (Test-Set Discipline). |
| 6 | What do the seeds 0, 1, 2 vary, and how was tuning done? | The split files are fixed; seeds change initialization and mini-batch order. Tuning is one run per config with seed 0, scaffold training set, scaffold validation only, at most 8 configs per model, chosen by mean validation PR AUC. The same config is reused on the random split. | `src/dl/run.py` (`GRIDS`, tune mode); `src/dl/train.py::set_seed`; `results/best_configs_dl.json`. |

## 2. Models

| # | Question | Short answer | Evidence |
|---|---|---|---|
| 7 | How does the GCN work, and why is it in the study? | L `GCNConv` layers, each followed by batch norm, ReLU and dropout, then a mean readout and a two-layer head. It uses atom features only and ignores bond features, so it is the simple graph baseline. Frozen config: hidden 256, 3 layers. | `src/dl/models.py::GCN` (docstring: "graph convolution baseline"); `results/best_configs_dl.json` (`gcn\|none`); `report/references.bib` (`kipf2017gcn`). |
| 8 | How does the MPNN work (edge network, GRU, Set2Set)? | Atoms are embedded to h dimensions. For T steps with shared weights, an edge network (two-layer MLP from the 6 bond features to an h x h matrix) turns neighbour states into messages (mean aggregation) and a GRU updates each atom. A Set2Set readout (3 processing steps) pools atoms into a 2h graph vector; dropout and a two-layer head give 12 logits. Frozen config: hidden 64, T = 3, no edge dropout. | `src/dl/models.py::MPNN`; `results/best_configs_dl.json` (`mpnn\|none`); `report/references.bib` (`gilmer2017neural`, `cho2014gru`, `vinyals2016set2set`). |
| 9 | Why an FP-MLP? | It is the deep-learning control: an MLP on the fingerprint and descriptor vector with no graph structure. If a graph model cannot beat it, message passing is not what helps. The finals use Morgan bits plus the 213 descriptors (2,261 inputs). | `src/dl/models.py::FPMLP` (docstring); `results/dl_results_test_ranajeet_fpmlp.csv` (`fpmlp+both`); `report_phase2/sections/hybrid.tex`. |
| 10 | What is H1, and why does the MPNN need descriptors? | The MPNN encoder plus a branch for the RDKit descriptors (linear to 128, ReLU, dropout) concatenated with the graph vector before the head. The idea is that whole-molecule properties are hard to rebuild from local message passing. H1 has no config of its own: it reuses the `mpnn\|none` entry because `best_configs_dl.json` has no `mpnn\|desc`. | `src/dl/models.py::MPNN` (`extra_dim`); `src/dl/run.py` (`best.get(key) or best[f"{model}\|none"]`); `report_phase2/sections/hybrid.tex` (motivation; the oversmoothing argument there is **UNVERIFIED** from the repo). |
| 11 | How does H2 work and how was its partner chosen? | No training: for each endpoint the scores of the Phase 1 XGBoost (morgan+desc) and of one deep model are replaced by ranks scaled to (0, 1] and averaged 0.5 / 0.5. The partner is the deep model with the best mean peak validation PR AUC over seeds 0-2 from the final-run curves on the scaffold split; that returned the FP-MLP (`ens_xgb_fpmlp+both`). The margin over H1 is below the seed std, so the XGBoost + H1 pairing is reported as a secondary variant. | `src/dl/ensemble.py` (`rank_norm`, `fuse`); `report_phase2/sections/hybrid.tex` (H2 subsection); I recomputed the peak validation PR AUC from `results/curves/*_final.json` and the scaffold ordering matches `hybrid.tex`. |
| 12 | Why equal weights and no tuning for H2? | Weights fixed a priori mean nothing is fitted on validation or test, so the ensemble cannot leak. The cost, which the report states, is that equal weights dilute the stronger tree model (see question 18). | `src/dl/ensemble.py` (docstring); `report_phase2/sections/hybrid.tex`. |

## 4. Pitfalls and limitations

| # | Question | Short answer | Evidence |
|---|---|---|---|
| 21 | How was test-set leakage prevented? | Tune mode never scores the test split; `--mode final` and `--mode ablate` need `--i-know-this-touches-test` and exit unless `results/best_configs_dl.json` exists; the Makefile guard (`dl-guard`) also requires that file to be committed and unchanged. Descriptor scaling and imputation are fit on the training partition only, `pos_weight` uses training labels only, early stopping uses validation, and the H2 partner was picked from validation curves. Limit: the code checks that the file exists, not that it was committed before running; the commit order is the evidence. | `src/dl/run.py`; `Makefile` (`dl-guard`); `src/features.py` (Phase 1); `README.md`; commit `0aebd87`. |
| 22 | What are the limits of 3 seeds and one tuning seed? | Seed std only measures model randomness: there is one fixed scaffold split and one fixed random split. Each config is tuned from a single seed-0 run, so selection can be noisy (the H2 partner margin of +0.0037 was below the seed std). With 12 endpoints the paired tests are low-powered. | `README.md` (limitations); `src/dl/run.py` (`seed=0` in tune); `report_phase2/sections/hybrid.tex`; `src/dl/analysis.py::paired_endpoint_test` (docstring: low-powered). |
| 23 | Is H1 fairly tuned? | No: H1 reuses the MPNN's frozen config, because the frozen file has no `mpnn\|desc` entry. So H1 may be under-tuned relative to its best possible config. | `src/dl/run.py` (fallback to `{model}\|none`); `results/best_configs_dl.json` (keys: mpnn\|none, gcn\|none, fpmlp\|morgan, fpmlp\|both). |
| 24 | Can someone re-run your ablations exactly? | Not from a recorded command. The commands in `make dl-ablate` were reconstructed from the tag, variant and feature-set columns of the ablation CSVs; the original command lines are not in the repo. The ablations are scaffold split only. | `Makefile` (comment above `dl-ablate`); `results/dl_ablation_test_*.csv`. |
| 25 | What else would a sceptic challenge? | (a) Evidence that nothing ran on test before the freeze is the commit order only (question 5). (b) The random split is not tuned separately; scaffold configs are reused. (c) The ablations were run on the test split, so they are explanatory, not selection tools. (d) Which deep model wins H2 is decided on 3 seeds of validation curves. (e) Why the cap is 50 and why stopping uses PR AUC are not recorded (questions 3 and 4). | `CONTRACT.md`; `src/dl/run.py`; `report_phase2/sections/hybrid.tex`. |
